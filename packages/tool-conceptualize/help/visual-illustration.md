An illustration answers "what could it look like?". It is **illustrative**: never to scale, never
geometry, never evidence, and it never marks a requirement as satisfied or a design as feasible.

**Owner decision for this release:** structured layouts are the primary visual and there is no live image
generation. When the assistant or a person requests an illustration, the visualization service's reason is
shown (for example *not connected*, *images disabled*, *method unsupported*: Sign in with ChatGPT cannot
generate images, or *provider missing*), the request is refused, and nothing is charged. The layouts keep
working.

When generation is configured, `conceptualize.request_illustration` composes the instruction from the
structured definition only (intent, principle, components, connections), creates an illustration visual
pinned to the Concept revision, and starts a job. The card shows the job state; a failed or cancelled
image never affects the other alternatives, and an identical request never generates or charges twice.
Conceptualize stores only the asset ID and its SHA-256.

Development and tests use a fake adapter whose images are marked **TEST ASSET**; it is never offered to
people outside development.
