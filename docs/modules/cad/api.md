# CAD Modeler: command and query API specification

Status: Proposed with ADR-0023. Authoritative definitions: `packages/cad-core/src/commands/registry.ts`
(commands) and `catalog.ts` (queries). Machine-readable catalogue with every input JSON Schema,
precondition and error code: [commands.json](commands.json) (regenerated by `npm run cad:commands`,
kept current by a test). The same API serves the interface, the assistant and scripts.

## 1. Entry points

| Environment | Entry point |
| --- | --- |
| TypeScript (browser, Node) | `new CadEngine({ kernel, document })` from `@ews/cad-core`; kernels from `@ews/cad-kernel/node` (in-process) or `@ews/cad-kernel/worker-client` (Web Worker) |
| Pure transaction (no kernel) | `applyTransaction(doc, tx)` and `DocumentHistory` |
| Workspace assistant | `cad-modeler.*` actions ([ai-commands.md](ai-commands.md)) |
| HTTP (documents and revisions) | `services/cad` at `/api/cad/v1` (OpenAPI 3.1 at `/api/cad/v1/openapi.json`); see [service.md](service.md). Clients: `@ews/cad-client` (`createHttpCadClient`, `createLocalCadClient`). Commands are not executed on the server; the HTTP API stores and serves documents |

## 2. Transactions

```ts
interface Transaction {
  commands: { command: string; input: object }[] // 1–500
  expectedVersion?: number                         // optimistic concurrency
  label?: string                                   // undo history and log
  source?: 'user' | 'assistant' | 'script' | 'system'
}
```

- Validation order per command: known name → input JSON Schema → command preconditions.
- Atomic: the first failure returns `{ ok: false, error, failedIndex, failedCommand }` and nothing
  changes. Success increments `version` by exactly one and returns
  `{ ok, version, baseVersion, results[], affected: { created, modified, deleted }, refs }`.
- Placeholders: a command with `"ref": "$name"` binds `$name` to the first string field of its result
  (`sketchId`, `featureId` …). Later inputs may use `$name` or `$name.field[.index]` (for example
  `$rect.lines.0`, `$circle.center`).
- Determinism: IDs come from `nextId` (`sk-5`, `ext-21`); no clock or random input affects the model.
- Engine: `CadEngine.execute(tx)` also regenerates and returns `regeneration`.

## 3. Commands (39)

| Category | Command | Effect (summary) |
| --- | --- | --- |
| document | `set_document_metadata`, `set_document_source`, `clear_document_source` | title, description; source concept and handoff (revision-pinned provenance) |
| part | `create_part`, `rename`, `set_material` | parts, display names, material |
| parameter | `create_parameter`, `set_parameter`, `delete_parameter`, `bind_parameter`, `unbind_parameter` | expressions with cycle checks; revision-pinned bindings to other modules' artifacts |
| datum | `create_datum_plane` | reference plane offset from a standard plane, a datum or a planar face |
| sketch | `create_sketch` (on a standard plane, datum or planar face), `set_sketch_plane`, `add_regular_polygon` (fully constrained, across flats or circumradius), `add_point`, `add_line`, `add_circle`, `add_arc`, `add_rectangle`, `delete_sketch_entities`, `move_sketch_point`, `set_construction` | geometry |
| constraint | `apply_constraint`, `set_dimension`, `set_dimension_driving`, `delete_constraint` | constraints and dimensions |
| feature | `extrude_profile`, `revolve_profile`, `fillet_edges`, `chamfer_edges`, `pattern_linear`, `edit_feature`, `set_suppressed`, `delete_feature` | solids; fillets and chamfers on stable edge names; linear patterns with count and spacing expressions |
| semantics | `add_semantic`, `remove_semantic` | engineering meaning |
| reference | `add_reference`, `remove_reference` | links to other modules |

Each catalogue entry has `input` (JSON Schema), `output`, `preconditions`, `errors`, `undo`,
`effect: "mutation"`, `transactional: true`.

## 4. Session operations

`undo(source, expectedVersion?)`, `redo(...)` (new versions), `regenerate({ full })`,
`dryRun(tx)` (predicted bodies and failures before/after; never commits), `exportStep(partId?)`,
`mesh(bodyId)`, `open(document)`, `restore(content, label, source, expectedVersion)` (compensating
change). The tool session adds `newDocument`, `openText` (with format detection), `save`,
`exportStep` (download with structural inspection).

## 5. Queries (11)

`get_feature_tree`, `get_parameters`, `get_sketch`, `get_entities`, `get_mass_properties`,
`get_dependencies`, `get_failures`, `get_regeneration_summary`, `get_operation_log`,
`get_document`, `list_commands`, through `CadEngine.query(name, input)`. Inputs are validated
against their schemas (in the catalogue).

## 6. Errors

`{ code, message, details? }` with codes: `invalid-input`, `unknown-command`, `not-found`,
`precondition-failed`, `version-conflict`, `invalid-expression`, `cycle`, `in-use`, `unsupported`,
`invalid-document`, `nothing-to-undo`, `nothing-to-redo`, `kernel-unavailable`, `kernel-failure`,
`regeneration-failed`. Regeneration failures are not command errors: the command commits and the
feature reports `failed` / `blocked` with `details.reason` (`invalid-profile`, `upstream-failed`,
`upstream-suppressed`, `no-target-body`, `profile-crosses-axis`, `invalid-value`, `sketch-conflicting`,
`sketch-failed`, `invalid-shape`, `reference-lost` (a face or edge name no longer exists; details list
the available names), `face-not-planar`, `blend-failed`).

## 7. Versioning

The catalogue has `catalogVersion` (1.1.0: adds `create_datum_plane`, `fillet_edges`, `chamfer_edges`
and the plane options of `create_sketch` / `set_sketch_plane`; 1.2.0: adds `add_regular_polygon`,
`pattern_linear`, `bind_parameter`, `unbind_parameter` and the pattern fields of `edit_feature`; 1.3.0: adds
`set_document_source` and `clear_document_source`). Adding commands or optional inputs is a minor change;
removing or changing semantics is major and needs a deprecation period with both versions served.
