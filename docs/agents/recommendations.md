# Recommendations on the development approach and architecture

Requested by the owner via the coordinator (16 October 2026). Each item is checked against the data in the
[baseline](../status/context-baseline.md) and the repository history, and marked **implemented** (done in this branch),
**proposed** (needs a decision or work outside this agent's scope) or **rejected** (with the reason). "Measured" and
"estimate" are labelled; the claims about timeouts and merge queues come from the coordinator and are checked only as far as noted.

| # | Recommendation | Verdict | Check against data |
| ---: | --- | --- | --- |
| 1 | Sprint-scoped agents (fresh agent, brief plus status block, ends in a handoff); lower `autoCompactWindow` | **Implemented** (definition and rules); adoption is the coordinator's launch decision | Measured: module agents ran 2-3 days, 346-890 messages, 0-4 compactions, peak 958-967k. Estimate: 45% / 31% / 20% of all context tokens processed sat above 300k / 400k / 500k (`scripts/session-usage.mjs`), so a 400k cap removes up to about a third of context volume before counting the cost of more frequent summaries. `module-agent` sets `autoCompactWindow: 400000`; the status block and brief are in the [handoff template](handoff-template.md) |
| 2 | At most 2-3 concurrent implementation agents | **Implemented** (limit 3 module agents, in the [README](README.md#4-controls-against-duplicate-work-parallelism-and-loops)) | Measured: up to 8 agents live at once on 15-16 Oct; commit 1b1c984 records a test that "timed out under load"; 69 of 406 commits on main are `COORDINATOR REVIEW` and 71 are merges (16 "Merge main into"). Throughput per agent cannot be measured from transcripts, so the benefit is inferred, not measured |
| 3 | Model routing (Sonnet routine, Opus architecture/integration/review, Haiku search/log triage, research on Sonnet) | **Implemented** in `.claude/agents/` (`module-agent`, `task-worker`, `researcher`, `integration-runner` on Sonnet; `reviewer` on Opus; `scout` on Haiku) | Measured: 14 of 14 agents on Opus, 5 of them research sub-agents. Not measured: Sonnet's reliability on this repository. Use as a trial; the coordinator reviews the first Sonnet module sprint before widening. Haiku log triage works through `scout` (Grep) |
| 4 | Coordinator delegates verification to an integration runner | **Implemented** (`.claude/agents/integration-runner.md`, runs one suite at a time, returns a table) | Measured: coordinator tool results were 1.7M characters of Bash output and 13.2M of images; the coordinator also made 69 review commits. Delegation removes the output from its context; whether review quality holds is for the coordinator to judge |
| 5 | Visual checks as automated screenshot comparison with numeric results | **Proposed** | Measured: 13.2M of 15.2M characters returned to the coordinator were screenshots (image token cost is not derivable from base64 length). `tests/e2e` has no screenshot comparison (no `toHaveScreenshot` or pixel diff found). It needs test-infrastructure work (committed baselines, tolerance, update workflow), which is outside this agent's scope. Interim rule, implemented: read an image only when the visual result is the subject; otherwise assert on DOM or numbers |
| 6 | Reports capped at about 300 words plus links; progress files split into a one-page status and an archive | Cap **implemented**; split **proposed** | Measured: progress files are 26-55 KB (362 KB with the contracts files). The status block is defined in the template and `scripts/status-digest.mjs` gives a digest of about 8 KB for all modules. Splitting the existing files is for each owning agent at its next checkpoint, because those agents are running and own the files |
| 7 | One `verify` command with a compact summary; CI for full suites | Script **implemented**; npm alias and CI **proposed** | `node scripts/verify.mjs [typecheck] [test] [build] [e2e]` prints a table and the first failing lines, exit code 1 on failure (tested with synthetic steps; the real suites were not run in this worktree). Adding `"verify": "node scripts/verify.mjs"` to `package.json` is a one-line change left to the coordinator. CI: the repository has no `.github/`; GitHub Actions needs the owner's decision on hosting, and the e2e suite needs the embedded PostgreSQL, so start with typecheck, unit tests and build |
| 8 | Per-module registration manifests replacing append-only shared files | **Proposed** (architecture change; needs an ADR from the coordinator) | Measured churn on shared files: `packages/platform-sdk/src/boundaries.test.ts` 22 commits, `services/assistant/src/policy.ts` 29 commits across branches, `apps/workspace/src/platform/capabilities.ts` 7, `packages/platform-sdk/CHANGELOG.md` 13. High churn supports the diagnosis; actual conflict counts are not recorded in history, so the conflict claim is unverified. Risk to weigh: the boundary and catalogue tests are the governance that catches mistakes, so a manifest design must keep a single test that enumerates and validates all manifests |
| 9 | Module-owned contract packages; platform SDK keeps core types only | **Proposed**, not endorsed yet | Evidence is indirect: SDK 1.6 to 1.9 in three days and 13 CHANGELOG commits show contract changes are frequent. Against: ADR-0002 and the AGENTS.md "Contract changes" rules make one versioned SDK the single contract, and splitting it multiplies version matrices. A narrower first step is to let module-owned optional contract extensions live in the module with an SDK-level registration slot (the same mechanism as item 8). Needs coordinator and owner decision |
| 10 | Generate operation docs and help references from OpenAPI and operation schemas | **Proposed** | Already required in principle (AGENTS.md help rule 5: generate from authoritative definitions). Not measured: how much documentation is duplicated today. Needs a small audit by the owning agents of which help pages repeat schema content before building a generator |
| 11 | Fresh coordinator session per milestone from `docs/status/coordinator.md` | **Implemented** (handoff written; rule in [session-lifecycle](session-lifecycle.md)) | Measured: the coordinator reached 898k (90% of 1M) after 6 compactions, 24% of estimated cost. Start fresh at about 70% or at each milestone boundary; the handoff is the first file read |

## Order of value (estimate, judgement)

1. Items 1, 3 and 11 (context size and model) address the largest measured cost driver: long contexts.
2. Items 2 and 4 reduce coordinator load and test contention.
3. Items 5, 7 and 6 (split) reduce what enters context; they need small pieces of test and CI work.
4. Items 8-10 are architecture changes that cut merge work; decide them with an ADR and a pilot on one module, not a repository-wide rewrite.
