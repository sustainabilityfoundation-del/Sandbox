# GLB Model Viewer

A browser-based viewer for 3D models exported from SolidWorks as **GLB** (glTF 2.0 binary) files.
Built with React, TypeScript, Vite, three.js, React Three Fiber and Drei.

Models are processed entirely in the browser. Files are never uploaded anywhere, and the site
is a static bundle suitable for AWS Amplify Hosting.

This repository also contains the **Engineering Workspace** mockup at `/workspace/`, a
multi-tool interface built around a shared digital twin. It includes this viewer as one of its
tools. See [workspace/README.md](workspace/README.md).

## Features

- Open a `.glb` with the **Open model** button, or drag and drop it anywhere on the window
- Orbit (left drag), pan (right drag or Shift + drag) and zoom (scroll wheel or pinch)
- Fits the whole model automatically on load
- **Fit** (frame visible parts) and **Reset** (initial isometric view)
- Standard views: Front, Back, Left, Right, Top, Bottom and Isometric
- Solid and wireframe display, and an optional floor grid
- Model tree showing the exported assembly and component hierarchy with original names
- Click a part in the viewport or the tree to select and highlight it
- Hide and show components; **Show all** restores everything
- Status bar with file name, mesh count, triangle count and current selection
- Keyboard shortcuts: `F` fit, `W` toggle wireframe, `H` hide selection, `Esc` clear selection
- Clear loading and error states, with specific guidance for unsupported files
- Responsive layout (the model tree becomes a slide-over panel on narrow screens) and light/dark themes

### Supported files

| File | Supported |
| --- | --- |
| `.glb`: self-contained glTF 2.0 binary | ✅ |
| `.gltf` with separate `.bin` and texture files | ❌ Export as `.glb` instead |
| `.sldprt`, `.sldasm`: native SolidWorks | ❌ Export as `.glb` first |
| `.step`, `.stp`, `.iges`, `.x_t` and other CAD formats | ❌ |
| GLB with Draco or KTX2 compression | ❌ Not decoded in this version |

Meshopt-compressed GLBs are supported.

Measurement, sectioning and CAD editing are out of scope for this first version.

## Requirements

- Node.js 20.19 or newer (Node 22 or 24 LTS recommended)
- npm (bundled with Node.js)

## Install and run locally

```bash
npm install          # or `npm ci` to install exactly what package-lock.json specifies
npm run dev          # start the dev server at http://localhost:5173
```

Other scripts:

| `npm run preview` | Serve the production build locally at http://localhost:4173 |

## Sample model

If a file exists at `public/models/sample.glb`, the start screen shows a **Load sample** button.
If it doesn't, the start screen shows only the open instructions, and nothing breaks.

The repository includes a small **synthetic** bracket assembly at that path, generated by
`scripts/generate-sample.mjs`. It mimics a SolidWorks export (nested sub-assemblies, instance names
like `M8 Hex Bolt-1`, PBR materials, a multi-material part) but was not made in SolidWorks.
To use your own sample instead, replace `public/models/sample.glb` with any self-contained GLB.
Delete the file to remove the button.

`public/models/actuator.glb` is a second synthetic model, used by the Engineering Workspace.
Its node names start with digital-twin object IDs (for example `ROD-120 Rod`).

## Exporting a GLB from SolidWorks

SolidWorks 2019 and newer can export glTF directly:

1. Open the part or assembly in SolidWorks.
2. Choose **File › Save As**.
3. In **Save as type**, choose the GLB (glTF binary) option. Its exact wording varies by version.
4. Optionally click **Options…** to choose what to include, for example appearances.
5. Save, then open the `.glb` in this viewer.

Tips:

- Export **GLB** rather than glTF: the viewer needs a single, self-contained file.
- Assemblies keep their component tree and component names. Parts usually appear as one or more
  meshes, split by appearance.
- SolidWorks writes GLB in metres with Y up, which is what the viewer's standard views assume.
- Very large assemblies produce large files. Consider suppressing hardware and internal parts,
  or reducing the export quality, if a model is slow to load.

## Deploying to AWS Amplify Hosting

The repository includes an `amplify.yml` build specification:

- **preBuild:** `nvm install 22`, then `npm ci`
- **build:** `npm run build`
- **artifacts:** everything in `dist`

To deploy:

1. Push the repository to GitHub, GitLab, Bitbucket or AWS CodeCommit.
2. In the AWS console, open **AWS Amplify** and choose **Create new app**, then **Host web app**.
3. Connect your Git provider, then choose this repository and branch.
4. Amplify detects `amplify.yml`. Leave the build settings as they are and choose **Save and deploy**.
5. Each push to the connected branch triggers a new build and deploy.

Notes:

- The build has two static pages, `/` (viewer) and `/workspace/`. Neither uses client-side
  routes, so no rewrite rules are needed.
- The `nvm install 22` line makes the build use Node 22, which Vite 7 requires (20.19+).
  Remove it if your Amplify build image already provides a recent Node version.
- Without Git, you can run `npm run build` locally and drag the `dist` folder into Amplify's
  **Deploy without Git provider** option.

## Project structure

```
src/
  main.tsx, App.tsx          App shell and layout
  styles.css                 Theme tokens and component styles
  state/viewerStore.ts       Application state (Zustand): model, selection, visibility, view commands
  loading/                   Model loading. No React, unit tested.
    fileTypes.ts             Extension checks and unsupported-format messages
    glbHeader.ts             GLB container validation, self-containment and extension checks
    loadModel.ts             Parse with GLTFLoader from an in-memory buffer
    modelInfo.ts             Hierarchy, original names, mesh and triangle statistics
    dispose.ts               GPU resource disposal
    errors.ts                User-facing error types
  viewer/                    3D rendering (React Three Fiber)
    Viewport.tsx             Canvas, controls, axis gizmo
    ModelView.tsx            Renders the model; picking, visibility, wireframe, highlight
    CameraRig.tsx            Fit on load, standard views
    cameraMath.ts            Framing maths and view directions
    highlight.ts             Selection highlight and wireframe material handling
    Lighting.tsx             Studio environment and camera-following key light
    ModelGrid.tsx            Size-aware floor grid
  components/                Toolbar, model tree sidebar, status bar, empty/loading/error/drop overlays
  hooks/                     File drag-and-drop, keyboard shortcuts, colour scheme
scripts/generate-sample.mjs  Builds the synthetic demo models
src/workspace/, workspace/   Engineering Workspace mockup (see workspace/README.md)
```

### Resource handling

- Files are read into memory and parsed directly, so the app creates no object URLs for models.
  GLTFLoader revokes the temporary blob URLs it uses while decoding embedded textures.
- When a model is replaced, its geometries, materials and textures are disposed once React has
  unmounted it. Selection highlights use temporary material copies that are disposed when the
  selection changes.
